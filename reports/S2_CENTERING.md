> ⚠ **이 보고서의 transductive 수치는 참고용이며 논문 수치가 아니다.**
> 평가 데이터를 미리 본 값이 섞여 있다. 인용할 최종 값은
> [S13_FINAL_LADDER.md](S13_FINAL_LADDER.md) 와 `results/final_tables.csv` 다.

2026-09-25. 스크립트 [analyze_centering.py](../analyze_centering.py),
특징 캐시 [cache_ft_features.py](../cache_ft_features.py) (`cache_ft/`, 2.6 GB, 45개),
로그 `centering_analysis.log`, 결과 `results/centering_analysis.npz`.

학습 코드는 수정하지 않았다. A팔 체크포인트 45개(15 fold x 3 seed)만 쓴다.

## 왜 이 분석을 했나

1단계 진단은 held-out 피험자를 clip **0.755** 로 분류했는데, 같은 모델의 A팔 분류 head 는
clip **0.634** 였다. 진단은 head 가 쓰지 않은 두 가지를 썼다 — 테스트 도메인을 자기
**라벨 없는 평균**으로 다시 중심화했고, 훈련된 head 대신 **코사인 최근접 prototype** 으로
분류했다. 둘 중 무엇이 일하고 있는지, 아니면 결정 규칙이 달라서 생긴 허상인지 가른다.

네 조건이 이를 분리한다. 같은 체크포인트, 같은 세그먼트이며 결정 규칙만 바뀐다.

| | 중심화 | 분류기 |
|---|---|---|
| 1 | 없음 | 훈련된 head — **A팔 재현 (파이프라인 검증)** |
| 2 | 있음 | 훈련된 head |
| 3 | 없음 | 최근접 prototype |
| 4 | 있음 | 최근접 prototype — **진단 지표 1** |

중심화는 테스트 세션 자신의 **라벨 없는** 특징만 쓴다. EA 가 이미 요구하는 것과 같은
transductive 가정이므로 조건 2·4 는 배치 가능한 후보다 — 단, 캘리브레이션 녹화가 필요하다.

## 설계 결정

**raw 특징을 캐시한다.** `diagnose_prototypes.py` 는 추출하면서 L2 정규화하는데, 코사인
prototype 에는 맞지만 분류 head 에는 틀리다 — head 는 정규화되지 않은 CLS 로 훈련됐고
첫 LayerNorm 이 그 스케일을 기대한다. 그래서 raw 로 저장하고 소비 측에서 필요할 때만
정규화한다.

**처리 순서를 조건별로 고정했다.** 조건 4 가 진단 지표 1 과, 조건 1 이 A팔과 정확히 같도록:

```
prototype 경로 (3,4)  창 L2정규화 -> 클립 평균 -> 도메인 중심화
head 경로 (1,2)       raw 창 -> 중심화 -> head -> softmax -> 클립 평균
```

조건 2 의 중심화는 테스트 도메인 평균을 빼고 **학습 도메인들의 평균을 더해 되돌린다**
(도메인 평균들의 평균, 각 도메인 동등 가중). head 가 본 분포 위치로 옮기기 위해서다.

## 결과 3 (보완 2): 0.96 은 기울기 때문이다

| 역할 | 정렬 (clip, 중심화 최근접) |
|---|---|
| 학습 도메인 (역전파 받음) | **0.9612 ± 0.0543** |
| 검증 도메인 (기울기 없음, epoch 선택에만 사용) | **0.7988 ± 0.0549** |
| 테스트 도메인 (완전 미사용) | 0.7551 ± 0.0718 |

검증 도메인은 epoch 선택에 쓰였는데도 **테스트 쪽에 훨씬 가깝다.**
학습/검증 간격 **0.162** 대 검증/테스트 간격 **0.044** — 3.7배.

fine-tuning 은 **역전파를 받은 도메인만** 강하게 정렬시키고, epoch 선택을 통한 간접 노출은
거의 영향이 없다. 1단계에서 "학습 도메인 0.96" 이 과적합의 징후라고 본 해석이 이로써
확인된다.

## 결과 4 (강건성): 클래스 불균형에는 강건, 짧은 캘리브레이션에는 취약

### 클래스 불균형 — 문제 없다

캘리브레이션 녹화가 클래스 균형이라는 보장이 없으므로, 한 클래스를 세션당 5클립에서
2클립으로 줄여 중심화 평균을 계산하고 **전체 클립으로 채점**했다.

| 중심화 근거 | 조건 2 | 조건 4 |
|---|---|---|
| 균형 (5/5/5) | 0.7180 | 0.7590 |
| 부정 5→2 | 0.7160 (−0.002) | 0.7560 (−0.003) |
| 중립 5→2 | 0.7190 (+0.001) | 0.7565 (−0.003) |
| 긍정 5→2 | 0.7190 (+0.001) | 0.7432 (**−0.016**) |

최악이 −0.016 으로 감지 한계의 절반 이하다. **배치 관점에서 중요한 성질이다** —
캘리브레이션 녹화의 감정 구성을 통제할 필요가 없다.

### 짧은 캘리브레이션 — 안 된다

중심화 평균을 세션 앞 N초의 창으로만 계산하고, 평가는 **300초 이후로 고정**해
길이만 달라지게 했다(짧은 캘리브레이션이 더 많은·더 쉬운 구간에서 채점되지 않도록).

| 중심화 근거 | 조건 2 | 조건 4 |
|---|---|---|
| 앞 30초 | 0.5444 | 0.5402 |
| 앞 60초 | 0.5450 | 0.5566 |
| 앞 300초 | 0.6370 | 0.6492 |
| **세션 전체** | **0.7058** | **0.7487** |

30~60초로는 **조건 1(0.634)보다도 나쁘다.** 300초로도 전체의 절반밖에 회수하지 못한다.

기전은 EA 캘리브레이션 스윕에서 본 것과 같다. 세션 앞 300초는 클립 1~2개, 즉 **한 가지
감정만** 담고 있어 중심이 그 클래스 쪽으로 치우친다. 그때도 prefix 가 random 보다 훨씬
나빴다 (피험자 8 에서 prefix 20초 −0.131 vs random −0.002).

**중심화는 EA 보다 요구 조건이 엄격하다.** EA 는 8초 random 으로도 −0.015 에 그쳤다.

> **2026-09-27 단서.** 이 비교는 두 조작의 캘리브레이션 요구량을 **같은 조건에서 잰 것이
> 아니다** — EA 쪽 스윕과 중심화 쪽 스윕의 창 선택 방식이 다르고, 양쪽 모두 평가 클립을
> 배제하지 않았다. 둘을 같은 프로토콜에 넣은 측정은 S8 분석 B 에 있다.

## 정리

| 질문 | 답 |
|---|---|
| +0.125 가 어디서 오나 | **거의 전부 중심화.** 결정 규칙은 +0.005 (유의하지 않음) |
| 감지 한계를 넘나 | **clip 단위 넘음** (CI 하한 +0.092), window 단위 미달 (+0.029) |
| 음수 격차가 사라지나 | 7/15 → 2/15. 1단계 결론은 유지 |
| 0.96 의 정체 | 기울기. 검증 도메인은 0.799 로 테스트에 가깝다 |
| 클래스 불균형 | 강건 (최악 −0.016) |
| 짧은 캘리브레이션 | **불가.** 30초는 기준선보다 나쁨, 세션 전체 필요 |

**도메인 중심화는 학습 없이 clip 0.634 → 0.759 를 주는 실제 후보다.** 15명 전원이
개선되고 클래스 불균형에 강건하다. 조건은 두 가지 — **clip 단위 집계**와 **세션 전체
분량의 캘리브레이션 녹화**.

### 남은 의문

- window 단위 효과(+0.043)가 clip(+0.125)보다 작은 이유를 모른다. 둘 다 유의하므로
  "window 에서는 안 된다" 가 아니라 "clip 집계가 효과를 키운다" 로 읽어야 한다.
- 중심화가 왜 듣는지는 설명하지 않았다. 세션별 오프셋을 빼는 것이 EA(진폭 맞춤)가
  못 잡은 무엇을 잡는지 — 그 무엇이 특징 공간의 DC 성분인지, 상태 드리프트인지 모른다.
- 조건 2(head 유지)가 조건 4(prototype)보다 낮은 이유를 확인하지 않았다. head 를
  중심화된 분포에서 재학습하면 따라잡는지 시험해 볼 수 있다 — 학습 코드 수정이 필요하다.
