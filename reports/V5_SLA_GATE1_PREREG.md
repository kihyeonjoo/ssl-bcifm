# V5 gate 1 사전 등록: SLA (자극 시점 정렬) 가 감정 정확도를 올리는가

**고정 시각: 2026-10-04 13:00 KST** — 사용자 승인("진행.") 직후, 코드 작성·실행 전에 적는다.
제안서: [V5_METHOD_PROPOSAL.md](V5_METHOD_PROPOSAL.md).  성립성 진단(gate 0)은 감정 라벨·정확도를
쓰지 않았으므로 이 판정과 독립이다.

## 질문

캘리브레이션 영상의 시점 대응으로 추정한 세션 회전(SLA)이 (1) 중심화 위로 감정 분류 정확도를
올리는가, (2) 감정 라벨 방법(L3)에 더해지는가.

## 데이터와 프로토콜 (V4 와 같다)

- **주 입력: no-EA 팔** (`cache_ft_noea`, `cache_ft_seedv_noea`).  부 입력: EA 팔 (`cache_ft`, `cache_ft_seedv`).
- 추출: 테스트 피험자 난수 `1000·ts + sd`, 검증 피험자 `100000 + 1000·v + sd`, `draw()` 소비 순서
  동일 → V4 와 **같은 캘리브레이션 클립**.  반복 10 (검증 3), 시드 3, fold 15 / 16.
- 예산: 감정별 앞 20초 / 40초 / 클립 전체 (감정당 1클립).
- 주 지표: **clip accuracy** (조건4 prototype — 평균 특징 → 최근접 prototype).  부 지표: window accuracy.
- 학습 prototype P: `analyze_stratnorm.prototypes(…, train, "center")` (V4 와 같다).
- 중심화 μ_d: 캘리브레이션 창 평균 (V4 와 같다).

## 방법

1. **center** — (z − μ_d) → P.
2. **L3** — P'_c = l2( λ·l2(M_c) + (1−λ)·P_c ),  M_c = 캘리브레이션 창 중 감정 c 의 (z − μ_d) 평균.
   λ ∈ {0.25, 0.5, 0.75, 1.0}.  (부록 A 의 L3 와 같은 식, prototype 만 V4 경로.)
3. **SLA** — 템플릿 T: 그 fold 의 **학습 피험자**(train 역할) 특징을 도메인 평균으로 중심화한 뒤,
   같은 클립·같은 시점(클립 안 창 번호)에서 평균.  SEED 는 세 세션이 같은 영상이므로 세션을 합쳐
   평균, SEED-V 는 세션별.
   - X = 캘리브레이션 창의 (z − μ_d),  Y = 대응하는 템플릿 행에서 그 평균을 뺀 것
   - U = [X; Y] 의 상위 k 우특이벡터 (k 가 랭크보다 크면 랭크까지)
   - R = Procrustes(XU, YU), det(R) > 0 로 고정
   - W = (1−β)·I + β·(I − UUᵀ + U R Uᵀ)
   - k ∈ {10, 20, 50},  β ∈ {0.25, 0.5, 0.75}
   - 평가: (z − μ_d) W → P
4. **SLA+L3** — SLA 의 W (SLA 로 선택된 k, β 고정) 를 적용한 공간에서 L3.  M_c 도 W 적용 후 평균.
   λ 는 따로 선택.

- **초매개변수**: fold 마다·예산마다, 검증 피험자 2명 × 반복 3 의 **window accuracy** 평균으로 고른다
  (S11·부록 A 의 선택 지표).  테스트 피험자는 선택에 쓰지 않는다.
- **자극 정체성은 캘리브레이션 클립에만 쓴다.**  평가 클립의 정체성·시점은 어디에도 쓰지 않는다.

## 검정

- 피험자 단위(시드 평균) 짝지은 Wilcoxon, 부트스트랩 95% CI, 이긴 수.
- **주 족 (Holm 6)**: SLA − center, 2 데이터셋 × 3 예산, clip.
- **부 족 (Holm 6)**: (SLA+L3) − L3, 2 × 3, clip.
- 기술 통계 (족 밖): L3 − center, SLA − L3, window 지표, EA 팔.

## 판정 (주 입력 = no-EA 팔)

- **A** = 두 데이터셋 모두 클립 전체에서 SLA − center ≥ **+0.015** 이고 Holm p < 0.05.
- **B** = (클립 전체에서 (SLA+L3) − L3 > 0, Holm p < 0.05 인 데이터셋이 하나 이상)
  **또는** (T40 에서 두 데이터셋 모두 SLA − center > 0, Holm p < 0.05).

| 판정 | 조건 |
|---|---|
| **진행** (방법 기여) | A 그리고 B |
| **부분** | A 이지만 B 아님, 또는 A 의 조건을 한 데이터셋만 만족 |
| **실패** | 그 외.  두 데이터셋 모두 클립 전체 Δ < +0.01 이면 SLA 경로를 **중단**한다 |

주 족이나 부 족에서 Δ < 0 이고 Holm p < 0.05 인 칸이 있으면 판정을 한 단계 낮춘다.

## 예측 (적어 둔다)

- SEED-V 에서 SEED 보다 크다 (테스트 세션 prototype 과 학습 prototype 의 코사인 0.32 vs 0.75).
- T20 은 대응점이 클립당 5창뿐이라 작거나 0.
- SLA+L3 > L3 (작더라도) — 두 정보가 다르다 (시점 응답 vs 감정 평균).

## 회귀 검사

center 는 V4 의 center (같은 입력) 와 **피험자별로 같아야 한다** — 같은 코드 경로·같은 추출이다.
어긋나면 실행을 멈추고 원인을 찾는다.

## 스모크 테스트 규칙

전체 실행 전에 파일 1개·반복 1회로 돌리되, **center 가 V4 와 일치하는지와 다른 방법이 유한한 값을
내는지만** 출력한다.  SLA·L3 의 정확도는 보지 않는다.

## 해석에 붙는 주의 — SEED 특징의 수치 정밀도 민감성 (13:20 발견)

사용자 질문("캐시로 계산하는데 재현해도 괜찮은가")을 확인하다가 찾았다.  체크포인트에서 특징을 다시
뽑아 캐시와 비교하니 (피험자 1, 세션 1):

| | SEED | SEED-V |
|---|---|---|
| CPU fp32 vs 캐시 (GPU bf16) 코사인 중앙 / 최소 | 0.984 / 0.020 | 0.9985 / 0.991 |
| **같은 코드 CPU fp32 vs CPU bf16** | 0.978 / −0.018 | 0.9957 / 0.973 |
| 코사인 < 0.9 인 창 비율 (fp32 vs 캐시) | **21%** | 0% |

- 창 순서·라벨은 완전히 같고, 캐시와의 차이는 **정밀도(bf16 ↔ fp32)만으로 같은 크기가 난다** —
  캐시는 지금 코드와 맞는다 (파이프라인 변경 아님).
- 그러나 **SEED 모델의 CLS 특징은 bf16 정밀도에 민감하다** (같은 입력에서 일부 창의 방향이
  바뀐다).  SEED-V 모델은 그렇지 않다.
- 캐시는 학습·평가 때와 같은 bf16 이고 모든 방법이 같은 특징을 쓰므로 **짝지은 비교는 유효하다.**
  하지만 fp32 나 다른 GPU 로 재현하면 SEED 수치가 달라질 수 있고, **SEED 의 SLA 무효과가 이 잡음
  때문인지는 이 실험으로 가를 수 없다.**  확인하려면 SEED 캐시를 fp32 로 다시 뽑아야 한다 (GPU).
- 확인한 것은 피험자 1 의 체크포인트 하나(seed0)다.  다른 fold 의 정도는 아직 모른다.

## 정밀도 점검 결과 (13:46) — 결론 불변

사용자 승인으로 SEED no-EA 팔을 **진짜 fp32** (bf16 autocast·TF32 끔) 로 다시 뽑았다:
`cache_ft_features.py --no_ea --fp32` → `cache_ft_noea_fp32/` (45개, GPU3 14분, 기존 bf16 캐시는 보존).

**특징 수준** (45 fold 전체): bf16 vs fp32 코사인 < 0.9 인 창은 평균 **1.0%** (파일별 0~2.9%).
