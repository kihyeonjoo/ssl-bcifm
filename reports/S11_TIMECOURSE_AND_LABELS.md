# 분석 C: 감정 신호는 영상 시작 직후가 아니라 시간이 지나야 올라온다

## 측정

테스트 피험자의 각 클립을 시간 구간으로 나누고, **세션 전체 중심화**(transductive)
기준으로 구간별 window 정확도와 그 구간 평균 특징의 클래스 여백(정답 클래스 코사인 −
나머지 두 클래스 평균 코사인)을 잰다.  구간 **사이의 상대 비교**가 목적이므로 중심화
방식이 구간마다 달라지지 않게 고정했다.

## 결과 — 단조 증가

| 구간 | window 정확도 | 클래스 여백 | 첫 구간 대비 | p | 이긴 수 |
|---|---|---|---|---|---|
| 0–20초 | 0.5150 ± 0.089 | +0.475 | — | — | — |
| 20–40초 | 0.5896 ± 0.087 | +0.653 | **+0.0747** | 0.0006 | 14/15 |
| 40–80초 | 0.6099 ± 0.079 | +0.764 | **+0.0950** | 0.0006 | 13/15 |
| 80–160초 | 0.6380 ± 0.067 | +0.881 | **+0.1230** | 0.0001 | 14/15 |
| 160초–끝 | 0.6866 ± 0.052 | +0.935 | **+0.1717** | 0.0001 | **15/15** |

첫 20초는 0.515 로 거의 쓸모가 없고 160초 이후는 0.687 이다.  **여백이 0.475 →
0.935 로 두 배**가 되므로 이것은 분류기 문제가 아니라 **특징 자체에 감정 신호가 덜
실려 있는 것**이다.

**S10 의 "고르게 뽑기" 결과가 이것으로 설명된다** — 창 개수를 같게 두고 위치만 뒤로
섞으면 신호가 무르익은 구간이 들어오므로 좋아진다.

## 그러나 앞부분을 버리면 안 된다

시청 시간 T 를 고정하고 처음 D초를 버렸을 때 (조건4, 반복 10):

| 60초 | window | 0.6251 | −0.0004 (p=0.33) | −0.0004 (p=0.49) |
| 120초 | window | 0.6267 | −0.0000 (p=0.56) | −0.0000 (p=0.42) |
| 40초 | clip | 0.7080 | −0.0032 (p=0.12) | **−0.0064 (p=0.025)** |
| 120초 | clip | 0.7241 | −0.0007 (p=0.57) | −0.0002 (p=0.82) |

**전부 0 이거나 약간 나쁘다.**  40초 시청에서 20초를 버리면 clip 이 유의하게 떨어진다.
창이 줄어 생기는 손실이 품질 향상을 상쇄한다.

> **캘리브레이션 영상 설계에 주는 답**: "앞부분을 버려라" 가 아니라 **"영상을 길게
> 보여줘라"** 다.  본 것은 다 쓰는 게 맞고, 짧은 영상 여러 개보다 긴 영상이 낫다 —
> 같은 40초라도 한 영상의 0–40초 구간은 신호가 무르익기 전이기 때문이다.

# 분석 D: 자극 라벨 캘리브레이션

## 전제

캘리브레이션 영상은 **실험자가 고른 것**이므로 각 창이 어떤 감정을 유도하려고
제시됐는지는 사용자 주석 없이 안다.  S10 의 M1·M2 는 이 정보를 쓰지 않고 pseudo-label
로 추정해 oracle 상한의 5~16% 만 회수했다.

**평가 클립의 라벨은 절대 쓰지 않는다.**  S10 의 oracle 회전은 `m2_apply(..., y_true=y)`
에서 `y` 가 `eval_keys` 의 라벨이었다 — **채점 대상 자신의 정답**을 본 도달 불가능한
상한이다.  여기 방법들은 전부 배치 가능하다.

## 방법

| | 내용 |
|---|---|
| L1 | 균형 기준점.  μ = 감정별 캘리브레이션 평균들의 평균 |
| L1m | M1 의 라벨 버전.  μ = mean_i( z_i − γ·P_{c(i)} ), c(i) 는 자극 라벨 |
| L2 | 회전.  캘리브레이션 감정별 평균 → 학습 prototype 으로 가는 Procrustes (부분공간 k, 수축 β) |
| L3 | prototype 혼합.  P_new = λ·(캘리브레이션 감정 평균, 길이를 ‖P‖ 로 보정) + (1−λ)·P |
| L4 | head 마지막 층을 캘리브레이션 창으로 적응, 원 가중치 쪽 L2 규제 |

초매개변수는 **방법마다 따로**, 각 fold 의 검증 피험자 2명으로 고른다.

## 왜 짧은 시청에서 실패하는가 — 분석 C 가 답한다

캘리브레이션 감정별 평균이 학습 prototype 쪽으로 얼마나 기울어 있는지:

| 시청 | 정답 클래스 코사인 | 여백 |
|---|---|---|
| 20초 | **0.482** | +0.712 |
| 40초 | 0.562 | +0.828 |
| 클립 전체 | **0.733** | +1.074 |

**자극 라벨은 맞는데 특징이 아직 그 감정을 담고 있지 않다.**  시청 20초의 캘리브레이션
평균은 정답 prototype 과 코사인 0.48 — 거의 무관한 방향이다.  그것을 목표로 회전(L2)
하거나 prototype 에 섞으면(L3) 잘못된 방향으로 끌고 간다.

분석 C 의 평가 클립 구간별 여백(0–20초 +0.475 → 160초+ +0.935)과 같은 곡선이다.
**두 분석이 같은 현상의 양면이다**: 감정 신호는 시간이 지나야 올라오고, 그래서
짧은 캘리브레이션은 라벨이 있어도 쓸 재료가 없다.

## L1 은 이 프로토콜에서 구조적으로 무효다

**감정별로 같은 길이를 떼면 L1(균형 기준점)은 단순 평균과 수학적으로 같다** — 각
클래스가 같은 창 수를 내므로 전체 평균이 곧 클래스 평균들의 평균이다.  검증에서
시청 20초·40초의 차이가 **정확히 0.00e+00** 으로 확인됐다.

클립 전체에서만 차이가 난다(2.31e−03) — 클립 길이가 제각각이라 단순 평균이 긴 클립
쪽으로 가중되기 때문이다.  그 차이도 효과로는 +0.0001 로 무의미하다.

**L1 은 캘리브레이션 길이가 감정별로 불균형할 때만 의미가 있다.**  이 프로토콜은
설계상 균형이므로 여기서는 잴 것이 없었다.

## 검정하지 않은 것

- **EA 는 transductive 다.**  이 분석은 전부 `cache_ft` 로 했다.  효과가 있는 설정
  (L4, 클립 전체)을 EA 현실적으로 다시 재려면 GPU 재인코딩이 필요하다 — 아직 안 했다.
- ~~L4 를 조건4 경로와 직접 비교하지 않았다~~ → **했다** (위 정정 표).  clip 에서는
  유의하지 않고 window 에서만 유의하다.
- L4 는 **마지막 층만** 푼다.  전체 head(41k 파라미터)를 푸는 변형은 재지 않았다.
- 분석 C 의 구간 경계(0/20/40/80/160초)는 임의로 정했다.  변화점을 추정한 것이 아니다.
- 분석 C 는 세션 전체 중심화를 썼다 — 구간 사이 비교를 위한 선택이고, 현실적
  프로토콜에서의 구간별 값은 아니다.

## 구현 기록

- `l4_head` 가 60 Adam 스텝에 **45초**였다.  200→3 선형층에 수백 행이면 밀리초 단위여야
  한다.  원인은 **torch 기본 스레드 28개(코어 56)와 작은 텐서의 조합**이다:
  56 스레드 45.08초, 8 스레드 0.436초, **4 스레드 0.124초** — 360배.
  `torch.set_num_threads(4)` 로 고정했다.
- 초매개변수 선택이 처음에는 모든 값마다 `run_methods` 를 통째로 불러 L4 의 미세조정이
  다른 방법의 격자에서도 돌았다.  방법별로 자기 격자만 계산하도록 고쳤다
  (체크포인트당 4분 이상 → 7.2초).
