# 평가 프로토콜 총정리

작성 2026-10-03.  모든 수치와 동작은 코드에서 확인했고, 해당 줄을 달아 두었다.
여기 적힌 것이 **논문 Methods 의 근거**다.

## 1. 입력 단위 — 4초 창

| | 값 | 근거 |
|---|---|---|
| 창 길이 | 800 샘플 = **4초** @ 200 Hz | `segment_length: 800` |
| 창 간격 | 800 샘플 | `step: 800` → **겹치지 않는다** |
| 채널 | 62 (SEED 순서) | `SEED_CH_NAMES` |
| LaBraM 패치 | 200 샘플 = 1초 → 창 하나 = 패치 4개 | `patch_size: 200` |

창은 클립 안에서 **시간순으로** 쌓인다 (`_add_segments` 가 `start += self.step` 로
전진하며 append).  그래서 인덱스 순서 = 시간 순서다.

| | 클립당 창 수 | = 초 |
|---|---|---|
| SEED | 46 ~ 66 | 184 ~ 264 |
| SEED-V | **13 ~ 74** | **52 ~ 296** |

SEED-V 는 클립 길이가 감정마다 다르다 — 5절을 보라.

## 2. 프로토콜

`--eval_mode` 로 고른다.  구현된 셋 중 **둘만 쓴다**.

### (a) `loso` — cross-subject (주 프로토콜)

피험자 한 명을 통째로 뗀다.

| | 구성 |
|---|---|
| test | 그 피험자의 **3세션 × 15클립 전부** |
| val | 테스트 피험자 **다음 2명** (순환, RNG 없음) |
| train | 나머지 전부 (SEED 12명, SEED-V 13명) |

검증 피험자를 순환으로 고르는 이유: 모든 피험자가 검증을 같은 횟수 맡고 난수가
개입하지 않는다 ([finetune_labram_hemi_aux.py:1175-1186](../finetune_labram_hemi_aux.py#L1175-L1186)).

### (b) `subject_dependent` — within-subject (문헌 비교용)

한 피험자 안에서 **클립**을 나눈다.  **두 데이터셋의 규칙이 다르고, 그 차이는
문헌의 것이지 우리가 만든 것이 아니다** (2026-10-03 확인, 11절에 출처).

| | 분할 | 세션 처리 | 폴드당 학습 | 폴드당 평가 |
|---|---|---|---|---|
| SEED | 클립 1-9 / 10-15, **1회** | **세션별로 따로 학습**, 결과를 세션 평균 | 9클립 (클래스별 3) | 6클립 (클래스별 2) |
| SEED-V | 클립 그룹 **3폴드** 1-5 / 6-10 / 11-15 | **3세션을 합쳐** 학습 | **30클립** (클래스별 6) | **15클립** (클래스별 3) |

측정으로 확인한 것 (`sd_folds`, `sd_val_split`):

- SEED-V 3분할은 **9개 (세션,폴드) 조합 전부** 클래스별 정확히 1클립이다
- 세션을 합치면 폴드당 학습 30클립(클래스별 6) / 평가 15클립(클래스별 3)
- 3폴드가 45클립(15 × 3세션)을 **정확히 한 번씩** 덮는다

**SEED 규칙을 SEED-V 에 쓸 수 없다.**  SEED-V 는 감정별 클립이 3개뿐이라 15클립을
5클래스로 9/6 으로 나누면 정수가 안 된다 (9÷5=1.8).  실제로 적용하면 어떤 감정은
학습 클립이 1개뿐이고, **부족한 감정이 세션마다 바뀐다** (세션1 은 disgust,
세션2·3 은 fear — 세션1 의 클립 순서가 다르다).

**세션 합침의 의미.**  SEED-V 의 SD 수치는 **피험자 안에서의 세션 간 일반화**를
포함한다.  S15 에서 같은 피험자의 세션 간 감정 방향 코사인(0.840)이 그 피험자 대
학습 풀(0.828)과 거의 같았으므로, 이것은 작은 차이가 아니다.  문헌이 그렇게
보고하므로 따르지만, **표에 "세션 합침" 을 명시해야 한다.**

**검증셋은 LOSO 와 다른 방식이다.**  SD 는 한 피험자 안에 있어서 뗄 다른 피험자가
없다.  그래서 **각 학습 클립의 뒤쪽 20% 창**을 검증으로 쓴다
(`sd_val_frac: 0.2`, `sd_val_split`).  이것은 학습과 상관이 높고, **epoch 선택에만**
쓰이며 평가 클립은 건드리지 않는다.  **표에 반드시 이렇게 적어야 한다.**

설정 키: `sd_train_per_session`(SEED), `sd_n_folds` + `sd_pool_sessions`(SEED-V),
`sd_val_frac`(둘 다).

### (c) `cross_session` — 쓰지 않는다

세션1 학습 / 세션3 평가.  구현돼 있으나 이 프로젝트에서 돌린 적이 없고,
`SEEDRawDataset` 하드코딩이 남아 있어 SEED-V 에 쓰면 안 된다.

## 3. Epoch 선택 — test 는 선택에 쓰이지 않는다

| | 동작 | 근거 |
|---|---|---|
| 검증 있음 | **검증 macro-F1 이 최대인 epoch** 의 test 수치를 보고 | [L820-836](../finetune_labram_hemi_aux.py#L820-L836) |
| 검증 없음 | 마지막 epoch 을 보고하고 **clip 지표가 아예 안 나온다** | `best_test_logits` 가 검증 분기 안에서만 채워짐 |
| 예산 | `epochs: 50`, `warmup_epochs: 5` | |

반환값이 `"accuracy": te_acc  # test @ best-val epoch` 이다
([L948-956](../finetune_labram_hemi_aux.py#L948-L956)).  로그의 `best=` 는 참고용이고
보고 수치가 아니다.

## 4. 지표 — 6개, 창 3개 + 클립 3개

CSV 열: `accuracy, f1_macro, window_balanced, clip_accuracy, clip_f1_macro, clip_balanced`

### 창 지표

창 하나가 한 표다.  라벨이 같은 창 ~58개를 독립 시행처럼 센다.

### 클립 지표 — 같은 모델 출력을 다르게 묶는다

재학습이 아니다.  **그 클립 창들의 softmax 를 평균해 argmax 를 취한다**
([L529-556](../finetune_labram_hemi_aux.py#L529-L556)):

```python
for key in sorted(set(zip(session, clip))):
    m = (session == key[0]) & (clip == key[1])
    cp.append(P[m].mean(0).argmax())   # 클립 하나당 예측 하나
    ct.append(y[m][0])                 # 라벨은 클립 내내 같다
```

실측 예 (피험자1 세션1 클립11, 정답 neutral, 창 58개): 창 예측은 neu 51 / neg 7 로
창 정확도 0.879, softmax 평균 [0.149, **0.815**, 0.036] → 클립 결정 neu (맞음).

### balanced accuracy

**클래스별 재현율의 평균** — EEG-FM 벤치마크가 B-Acc 로 보고하는 그 값이다
(`aggregate_logits.balanced`).  클래스가 불균형일 때 맨 accuracy 와 갈린다.

**코드 주석이 못박아 둔 원칙: "Report both, never one in place of the other."**

## 5. 결정 수와 우연 수준

| | 평가 창 | 평가 클립 | 클립 한 칸 |
|---|---|---|---|
| SEED LOSO | 2,526 | **45** | 2.2% |
| SEED-V LOSO | 1,823 | **45** | 2.2% |
| SEED SD | 1,029 | **18** | 5.6% |
| SEED-V SD | 1,823 | **45** | 2.2% |

창·클립 수가 피험자마다 똑같다 (범위 폭 0) — 같은 영화를 같은 공식 타임스탬프로
자르기 때문이다.

SEED SD 가 18개인 이유: LOSO 는 **사람 전체**를 떼므로 15클립이 전부 평가용인데,
SD 는 같은 사람 안에서 9클립을 학습에 쓰므로 세션당 6개만 남는다 (6 × 3세션 = 18).
SEED-V SD 는 3폴드가 45클립을 한 번씩 덮으므로 LOSO 와 같은 45개다.

### 우연 수준 — 창과 클립이 다르다

| | 클립 | 창 (최다 클래스) |
|---|---|---|
| SEED | 0.333 | 0.344 |
| **SEED-V** | **0.200** | **0.261** |

SEED-V 는 sad 클립이 happy 의 약 2배 길이라 **클립은 균형이지만 창은 불균형**이다
(sad 7,616창 대 happy 4,816창).  그래서:

- **창 단위 주 지표는 balanced accuracy** (기준 0.200)
- 맨 창 accuracy 를 적을 때는 기준을 **0.261** 로 명시
- **창 단위에서 "우연의 n배" 표현은 금지** — 0.3038 을 0.200 과 대면 1.52배,
  0.261 과 대면 1.16배다

SEED 는 0.344 로 균등 0.333 에 가까워 이 문제가 없다.

## 6. 시드와 집계

| | |
|---|---|
| 시드 | `[0, 1, 2]` — 가중치 초기화·dropout·drop-path·셔플 순서를 고정 |
| 1차 집계 | **피험자별로 시드 평균** → 피험자 하나당 수치 하나 |
| 2차 집계 | 피험자 간 평균 ± sd |
| 잡음 하한 | **한 피험자 안의 시드 sd** |

두 평균이 서로 다른 질문에 답한다 ([L1299-1307](../finetune_labram_hemi_aux.py#L1299-L1307)):
조건 간 비교는 1차(피험자 단위)에서 짝지어야 하고, 주장한 개선폭은 시드 sd 를
넘어야 한다.

측정된 시드 sd:

| | 창 | 클립 |
|---|---|---|
| SEED LOSO | 0.0284 | 0.0634 |
| SEED-V LOSO | 0.0233 (최대 0.0624) | 0.0511 (최대 0.1237) |

## 7. 통계 검정

| | |
|---|---|
| 기본 | **피험자 단위 짝지은 Wilcoxon**, 양측 α=0.05 |
| 함께 보고 | 부트스트랩 CI, 이긴 피험자 수 (예: 13/15) |
| n | SEED 15, SEED-V 16 |

**두 종류의 비교를 구분한다:**

| | 뜻 | 최소 감지 효과 |
|---|---|---|
| 결정 규칙 비교 | 같은 체크포인트에서 집계·중심화만 바꿈 | 쓰지 않는다 (짝지은 검정으로 충분) |
| **재학습 비교** | 다른 학습 실행끼리 (EA 있음/없음 등) | **쓴다** |

SEED 의 재학습용 최소 감지 효과 = **+0.0386** (n=15, α=0.05, power=0.80).
SEED-V 값은 짝지은 차이의 sd 가 필요하므로 **no-EA 팔이 끝나야 계산된다.**

## 8. transductive 와 realistic — 논문 수치의 경계

| | 무엇을 쓰는가 | 논문에 쓸 수 있나 |
|---|---|---|
| **transductive** | 평가 데이터로 EA 의 R̄ 나 중심화 μ 를 추정 | **아니다** |
| **realistic** | 캘리브레이션 창에서만 추정 | 그렇다 |

`ea_scope: session` 은 (피험자, 세션) 마다 R̄ 를 **그 세션 전체**에서 추정한다
([data/seed_raw_dataset.py:256](../data/seed_raw_dataset.py#L256)).  그래서 raw 학습
실행의 수치(SEED clip 0.6336 등)는 **transductive EA 를 포함한다.**  S0–S12 보고서의
수치는 참고용이고, 논문 수치는 S13 의 사다리다.

## 9. 캘리브레이션 예산 — 시청 시간으로 센다

**"라벨 없음" 의 범위.**  중심화의 μ 는 라벨을 쓰지 않지만, 캘리브레이션 클립을
**감정별 한 편씩** 고르는 것은 **자극 라벨을 쓴다**.  사용자 주석이 필요 없다는
뜻이지 라벨 정보가 전혀 안 들어간다는 뜻이 아니다 — 표현을 그렇게 적는다.

예산은 **클립당 초**다 ([calib_common.py:66](../calib_common.py#L66)).  감정별 1클립을
떼므로 클립당 초를 고정하면 감정별로 균형이다.

| 구간 | 감정별 | SEED 총 | SEED-V 총 | 감정 균형 |
|---|---|---|---|---|
| 1 | 20초 | 60초 | 100초 | 구성상 균형 |
| 2 | 40초 | 120초 | 200초 | 구성상 균형 |
| 3 | 클립 전체 | 11.2분 | **13.4분** | SEED 균형 / **SEED-V 아니오** |
| 3-대조 | 52초 | — | 260초 | 완전 균형 (SEED-V 전용) |

SEED-V 의 3번 구간만 감정 비율이 0.139~0.268 로 벌어진다 (SEED 는 균등에서 0.011
이내).  그래서 '감정별 52초' 를 균형 대조군으로 함께 돌린다 — 52초가 **잘림 없이
(0/720 클립) 균형을 유지할 수 있는 최대**다.

창 선택 규칙은 `prefix` (클립 앞부분) 와 `spread` (클립 전체에 고르게) 두 가지다
(`pick_from_clip`).

## 10. 한눈에

```
원시 EEG → 4초 창 (62ch × 800, 겹침 없음)
             │
             ├─ 창 지표 3개 : accuracy / macro-F1 / balanced
             │
             └─ 클립별 softmax 평균 → argmax
                  └─ 클립 지표 3개 : accuracy / macro-F1 / balanced

프로토콜:  loso (피험자 1명 떼기)  |  subject_dependent (클립 쪼개기)
epoch  :  검증 macro-F1 최대 지점 (test 는 선택에 미사용)
시드    :  0,1,2 → 피험자별 평균 → 피험자 간 평균
검정    :  피험자 단위 짝지은 Wilcoxon + 부트스트랩 CI + 이긴 수
```

## 11. 프로토콜 출처

SD 규칙은 문헌에서 확인한 것이다 (2026-10-03).  **그 전에는 내가 SEED 의 9/6 규칙을
SEED-V 에도 쓰고 세션을 합치지 않는 코드를 써 두었고, 둘 다 틀렸다.**

| 확인한 것 | 출처 |
|---|---|
| SEED-V: 클립 15편을 앞 5 / 중간 5 / 뒤 5 로 나눈 3폴드, **각 폴드의 학습 데이터는 그 그룹의 클립을 세 세션에서 모아 이어 붙인 것** | [arXiv 2202.05400](https://arxiv.org/pdf/2202.05400) |
| SEED: **세션별로** 앞 9 trial 학습 / 뒤 6 trial 평가, 결과를 세션·피험자 평균 | [LibEER PresetSetting](https://github.com/XJTU-EEG/LibEER/blob/main/docs/PresetSetting.md), [arXiv 2410.09767](https://arxiv.org/html/2410.09767v1) |
| SD 는 trial(클립) 단위로 나눈다 — 창 단위로 나누면 같은 클립이 학습·평가에 걸친다 | [arXiv 2410.09767](https://arxiv.org/html/2410.09767v1) |

**검증셋 방식(각 학습 클립의 뒤쪽 20% 창)은 문헌 관행이 아니라 이 프로젝트의 선택이다.**
문헌의 SD 설정에는 검증셋이 없는 경우가 많다.  우리는 (1) epoch 선택을 test 에
의존시키지 않기 위해, (2) 검증 없이는 `_train_and_eval` 이 로짓을 남기지 않아
clip 지표가 아예 안 나오기 때문에 넣었다.  **그래서 표 각주에 반드시 적는다.**

| SEED SD | 135 | 미측정 | — |

LOSO 는 run 당 학습 창이 ~26,000 인데 SD 는 400(SEED) ~ 1,200(SEED-V) 이므로 SD 가
훨씬 가볍다.  **추정하지 말고 1명 먼저 돌려 재기로 했다.**

**재학습 비교의 두 팔은 epoch·시드를 줄일 수 없다.**  EA 하나만 달라야 하므로
`configs/seedv_noea.yaml` 은 `configs/seedv_a02.yaml` 과 주석 제외 4줄만 다르다.
그리고 50 epoch 은 낭비도 아니다 — A팔의 선택 epoch 은 중앙값 8 이지만 90분위 26,
최대 32 로, 6개 run 이 26 epoch 이후에 최적점을 찍었다.
